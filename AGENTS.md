# История изменений Life Assistant

При каждом завершённом обновлении пользовательского приложения обновляй
`web/src/inventory/releases.json`: новую запись ставь первой, прежние сохраняй.
Эта история показывается пользователю по кнопке «Что нового».
Пиши по-русски, кратко: что добавлено, изменено или исправлено; без имён файлов,
технических журналов и ещё не реализованных обещаний. Не включай правки только документации.

Начальная версия — 0.0.1. По правилу пользователя от 23 октября 2026 обычные
обновления, включая новые возможности, увеличивают только третье число на 1.
Второе число меняй исключительно по явной команде пользователя для особо
глобальных функций. Первое число самостоятельно не меняй. Ранее выпущенные
версии задним числом не перенумеровывай. Номер `build` растёт
при каждом таком обновлении. Версия меняется за завершённый набор изменений,
а не за каждую правку файла. Дата записи — дата готовности обновления.

Версия интерфейса и приложения macOS берётся из первой записи этого JSON.
Не меняй версию формата данных инвентаризации ради версии приложения.
`CHANGELOG.md` относится к исходному House Control; историю нашего приложения веди отдельно.

## Текущие ограничения пользователя

24 октября 2026 в чате «Сборка и ГИТ» пользователь разрешил повторную
Mac-сборку и публикацию обновления для пользователей на GitHub после
завершения работы над интерфейсом. Чат «Интерфейс» завершил 0.4.31/build37.
Разрешение относится к сборке и публикации этого выпуска, включая код,
тег и подписанный канал обновлений; режим сбора новых замечаний сохраняется.

24 октября 2026, после оформления 0.4.28, пользователь снова включил
режим сбора замечаний: «пока записывай че я нахожу замечаний и тд».
Новые замечания и пожелания записывать в `docs/tasks-inbox.ru.md`;
исправления и новые функции по этим замечаниям не реализовывать до
новой явной команды пользователя начать. Запись замечаний не меняет
версию приложения и не добавляется в историю обновлений.
Это текущий режим работы, имеющий приоритет над прежними разрешениями ниже.

Позже пользователь отдельно разрешил Liquid Glass: «давай сделаем,
идем дальше по замечаниям». Этот пункт выполнен в 0.4.30;
после него сохраняется режим записи следующих замечаний без реализации
до новой явной команды. Это разрешение не относится к Mac-сборке
или публикации на GitHub.

Следующей отдельной командой пользователь разрешил реализацию плана
«Компактные Все вещи и Категории». Выполнено в 0.4.31: плотная таблица
и плитки вещей, список и плитки редактора категорий. «Без места» и
«Архив» в задачу не входят. После выпуска снова собирать следующие
замечания без реализации до новой явной команды пользователя.

Пользователь новой командой «погнали. после этого собери версию под мак и
обнови гитхаб» разрешил реализацию задач №27–29, Mac-сборку и публикацию
этого выпуска на GitHub. Позже добавлено: встроенные полки, ящики, отсеки
и модули шкафов не являются вещами, скрыты из «Все вещи» и не имеют своей
цены. При очистке карты сохраняются только вещи в «Без места»;
мебель и отсеки — в корзину. Это разрешение имеет приоритет над
историческими ограничениями ниже. Версия выпуска — 0.4.3/build9.
Обычная дальнейшая работа остаётся сначала браузерной; отдельная
Mac-сборка и новая публикация требуют команды пользователя.

После завершения 0.4.2 пользователь снова включил сбор замечаний:
только записывай их в `docs/tasks-inbox.ru.md`, реализацию не начинай
до новой явной команды. Это ограничение имеет приоритет над прежним
разрешением ниже. Дальнейшие изменения сначала проверять в браузере;
Mac-приложение собирать отдельно по команде «Собираем Mac-приложение».
Запрет выгрузки на GitHub сохраняется. Запись замечаний не меняет версию
и не добавляется в пользовательскую историю обновлений.

После опроса из 25 карточек пользователь дал новую команду «начинаем».
Локальная реализация задач №18–26 разрешена; ответы сохранены в конце
`docs/tasks-inbox.ru.md` и имеют приоритет над прежними предложениями.
Сообщение «сделаю тебе модельку» пользователь отменил как случайное;
это не отменяет команду начать работу. Текущий локальный выпуск — 0.4.2.
Новые незапрошенные возможности не добавляй. Проверки с изменением данных
выполняй только на отдельной демонстрационной базе, не на квартире пользователя.
Не выгружай код, теги, релизы или
другие изменения на GitHub до отдельной явной команды пользователя на выгрузку.
Разрешение начать локальную реализацию само по себе не снимает запрет публикации.
