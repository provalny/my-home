Дата: 23 октября 2026. Статус: реализовано в 0.3.0, проверено.

В разделе «Квартира» добавить общий процент и прогресс-бар заполненности непосредственно под сводкой панели «Комнаты и хранение» (стоимость и количество вещей/мест хранения), над списком комнат. Расчёт должен совпадать с общей заполненностью на обзоре.

По последнему скриншоту пользователя полосы отдельных комнат уже есть: спальня показывает 20%, остальные комнаты — «не указана». Отсутствует именно общая метрика панели. Сохранить полосы комнат и мест хранения, не скрывать их при неизвестном значении.

## 4. Связать значки категорий с вещами во всём приложении

Дата: 23 октября 2026. Статус: реализовано в 0.3.0, проверено.

Сейчас тематические значки видны в редакторе категорий, но вещи в остальных разделах продолжают показывать прежние общие значки коробки, папки или мебели. Использовать единое соответствие категории/подкатегории и значка во всём интерфейсе: таблица и сетка вещей, карточка, списки хранения, обзор, архив, корзина и выбор места, где применимо.

При смене категории значок вещи должен обновляться во всех представлениях. Подкатегория использует собственный тематический значок, если он предусмотрен, иначе наследует значок родителя. Для вещи без категории нужен понятный общий значок. Если есть фотография вещи, сохранять приоритет фотографии над значком. Не подменять заданную категорию догадкой по названию вещи.

Референс: вложение пользователя «Снимок экрана — 2026-10-23 в 15.26.00.png». Пользователь подчёркивает, что проблема проявляется не только в показанной таблице.

Дополнительное воспроизведение: на вложении «Снимок экрана — 2026-10-23 в 15.28.10.png» только что созданная вещь «ЛАйк» с явно выбранной категорией «Одежда / Футболки» в списке хранения тоже показывает общий значок коробки. Это не только проблема обновления старых карточек. При проверке охватить создание новой вещи с категорией, уже существующие вещи и последующую смену категории; во всех местах должен отображаться связанный тематический значок.

## 5. Разделить формы вещи и места хранения

Дата: 23 октября 2026. Статус: реализовано в 0.3.0, проверено.

Разные кнопки добавления вещи и отсека сейчас приводят практически к одному окну «Добавить вещь». Сделать формы различимыми по назначению, заголовку, основным полям и тексту действий, а не только по выбранному значению поля «Тип».

- Для обычной вещи: форма карточки предмета с категорией, фото и соответствующими характеристиками.
- Для полки, ящика и контейнера: форма добавления места хранения с названием, типом места, родительским местом и заполненностью. Второстепенные данные не должны перегружать основной сценарий.
- Не подставлять последнюю категорию вещи (например, «Одежда / Футболки») в новую структурную полку только потому, что её использовали при добавлении предмета.
- Сохранить ранее согласованную возможность собственной карточки, цены и фото у физических контейнеров, мебели и техники; разделение форм само по себе не должно убирать эти данные или возможности.
- Проверить также редактирование существующей вещи и места хранения: название окна и набор основных полей должны соответствовать объекту. Сохранить защиту черновиков и «Создать ещё».

## 6. Уплотнить форму вещи и пересмотреть видимость характеристик

Дата: 23 октября 2026. Статус: реализовано в 0.3.0, проверено.

В форме добавления вещи слишком много воздуха. Уменьшить лишние отступы и рациональнее расположить поля, сохранив читаемость и удобство ввода. Освободившееся место использовать для характеристик, которые часто нужны для выбранной категории: они должны быть доступны сразу, без раскрытия общего блока «Цена, состояние и характеристики».

Редкие/второстепенные характеристики скрывать в раскрываемом блоке «Дополнительно», сохраняя возможность заполнить и отредактировать их. Приоритет полей должен соответствовать категории; например, у одежды прежде всего уместны размер, цвет и бренд. Примеры не означают окончательного закрепления порядка полей. Не добавлять автоматическое отслеживание частоты использования или новые произвольные поля без отдельного решения.

Согласовать с задачей №5 о разделении форм: компактность и приоритет полей должны учитывать назначение окна. Сохранить необязательное фото рядом с названием, защиту черновика и существующие значения скрытых полей.

Референс: вложение пользователя «Снимок экрана — 2026-10-23 в 15.36.08.png» с формой добавления футболки.

Дополнение к задаче №6, референс «Снимок экрана — 2026-10-23 в 15.37.21.png»:

- Уплотнить также раскрытую подробную часть формы: уменьшить лишние промежутки между полями и сократить необходимую прокрутку.
- Вместо текстовой строки «Цвет» сделать компактный выбор цветовых образцов: 10–15 классических цветов и один отдельный вариант «Мультицвет».
- У каждого образца должно быть понятное название, у выбранного — отчётливая отметка. Мультицвет обозначить многоцветным образцом. До выбора значение остаётся неизвестным, не выбирать первый цвет автоматически.
- При редактировании сохранить ранее введённые текстовые значения цвета, пока пользователь сам не выберет новый вариант. Не терять их при переходе на палитру.

## 7. Раздел «Награды» и достижения за использование приложения

Дата: 23 октября 2026. Статус: реализовано в 0.3.0, проверено.

Добавить отдельный раздел «Награды» с компактными карточками достижений: значок, название, короткое условие, прогресс и отметка получения. Награды носят поощрительный характер и не ограничивают доступ к возможностям приложения. Пользователь просит придумать перечень и обеспечить пересчёт после обновлений без нарушения работы приложения.

Предлагаемый начальный перечень:

| Постоянный ID | Название | Условие |
| --- | --- | --- |
| first-item | Начало порядка | Внести первую собственную вещь. |
| items-10 | Всё под рукой | Учесть 10 вещей. |
| items-50 | Домашний каталог | Учесть 50 вещей. |
| items-100 | Хранитель дома | Учесть 100 вещей. |
| first-room | Первая комната | Разместить хотя бы одну собственную вещь в настоящей комнате. |
| rooms-3 | Осваиваем квартиру | Разместить собственные вещи в трёх комнатах. |
| storage-5 | По полочкам | Использовать пять разных мест хранения, в каждом есть хотя бы одна вещь. |
| storage-depth-3 | Матрёшка | Разместить вещь по цепочке из трёх вложенных мест хранения, например шкаф → полка → коробка. Комната в эти три уровня не входит. |
| all-placed | Всё на своих местах | При наличии минимум 10 активных вещей ни одна не находится в разделе «Без места». |
| categories-5 | По разрядам | Использовать пять разных основных категорий у активных вещей. Подкатегории одного родителя не увеличивают этот счётчик. |
| photos-10 | Узнаю с первого взгляда | Добавить фотографии к 10 вещам. |
| prices-10 | Знаю цену | Указать цену покупки или текущую оценку у 10 вещей. Неизвестная цена не равна указанному нулю. |
| attributes-10 | Всё в деталях | Заполнить хотя бы одну подходящую готовую характеристику у 10 вещей, например размер или цвет. |
| rooms-fill | Вижу заполненность | Указать заполненность всех настоящих комнат при наличии хотя бы одной. Значение 0% тоже учитывается; заполнять комнаты до 100% не требуется. |
| expiry-3 | Свежесть под контролем | Указать срок годности у трёх активных вещей. Дожидаться просрочки не требуется. |
| warranty-3 | Гарантия под рукой | Указать дату окончания гарантии у трёх активных вещей. |
| first-move | Новое место | Выполнить первое перемещение вещи, подтверждённое историей. |
| first-backup | Запасной ключ | Успешно сохранить первую резервную копию. Выбор папки или неудачная попытка не засчитываются. |

Правила подсчёта и устойчивости:

- За основу брать реальные данные пользователя. Готовые демо-данные сами по себе не должны выдавать весь набор наград; при реализации явно определить способ отделения демонстрации от собственной квартиры.
- Обычные вещи, физическая мебель и техника учитываются как предметы по одному разу. Структурные полки, ящики и служебные отсеки не увеличивают счётчик вещей. В наградах за текущее состояние не учитывать архив, корзину и виртуальные комнаты. Проверку хранения выполнять по всей вложенности без повторного подсчёта одной вещи.
- У каждой награды постоянный ID, независимый от названия, перевода, порядка и версии приложения. При переименовании категорий опираться на их ID и связи, а не текстовые названия.
- Прогресс считать отдельным безопасным расчётом по текущим данным и доступной истории. Повторный расчёт не создаёт дубликаты, не меняет вещи, цены, заполненность или историю имущества.
- Пересчитывать при изменении соответствующих данных, запуске после обновления, импорте и восстановлении копии. Сохранённый прогресс может быть только восстановимым кэшем; без него приложение обязано работать.
- Уже полученные награды сохранять отдельно по ID; последующее перемещение или удаление вещи не забирает награду. Актуальный прогресс условий пересчитывать отдельно от отметки о прежнем получении. Записи о получении включать в резервные копии.
- Для старых данных без записей наград восстановить подтверждаемые достижения из состояния и истории. Не придумывать дату получения, пропущенные действия или несуществующие успешные копии. Старую неподтверждаемую активность не засчитывать.
- При добавлении новых наград автоматически проверять их условия. Изменение существенного условия существующей награды оформлять отдельным ID или явным правилом совместимости, сохраняя ранее выданные достижения.
- Отсутствующие поля и неизвестные ID обрабатывать без сбоя. Ошибка расчёта наград не должна блокировать запуск, открытие каталога, сохранение данных или восстановление копии. Не требовать сброса квартиры после обновления.

При реализации проверить обновление старой квартиры без наград, повторный пересчёт без дубликатов, изменение и удаление вещей, добавление новых наград, импорт и восстановление копии.

## 8. Публичный GitHub, простая установка и обновления всего приложения

Дата: 23 октября 2026. Статус: реализация и публикация.

Пользователь разрешил публичный репозиторий в своём аккаунте, автоматические сборки релизов и обновление из Mac-приложения. Создан форк provalny/my-home; происхождение House Control и MIT сохраняются. README на русском и английском начинается с трёх шагов установки, с отдельным объяснением обновления всего приложения и сохранности квартиры. Инструкции сборки вынесены в документацию разработчика.

Требования: универсальное приложение для Apple silicon/Intel, DMG с переносом в «Программы», ZIP для Sparkle, подписанные архивы обновлений, автоматические тесты и сборки GitHub Actions, соответствие версии тегу и единому releases.json. Выпуск нового тега публикует релиз и канал обновлений. Пользователь отдельно разрешил права GitHub CLI и передачу выделенного ключа подписи в зашифрованный секрет Actions этого репозитория. Закрытый ключ не входит в Git и артефакты.

Новые 3D-модели только обсуждались; в этот этап не входят.
